# Citation Policy

Version: 1.0

Project: SciOS (Scientific Cognitive Operating System)

---

# Overview

This document defines the citation policy for the SciOS Research Platform.

Proper citation ensures that authors, contributors, and institutions
receive appropriate academic credit for their work while supporting
scientific transparency, reproducibility, and long-term sustainability.

---

# Objectives

The goals of this policy are to:

- Promote responsible academic attribution.
- Encourage reproducible research.
- Standardize software citation.
- Preserve research provenance.
- Support FAIR research principles.
- Enable traceability of scientific artifacts.

---

# Scope

This policy applies to all research outputs produced within SciOS,
including:

- Source Code
- Software Releases
- Documentation
- Scientific Papers
- Technical Reports
- Figures
- Tables
- Equations
- Datasets
- Benchmarks
- Models
- Workflows
- Notebooks
- Supplementary Materials

---

# How to Cite SciOS

Researchers using SciOS should cite both:

- The SciOS software.
- The relevant scientific publication(s), when available.

Citation metadata is maintained in:

```
CITATION.cff
```

located at the project root.

---

# Preferred Citation

The preferred citation should always reference the latest stable release.

Example:

```
Bui Dinh Hoang.

SciOS: Scientific Cognitive Operating System.

Version X.Y.Z.

2026.

https://github.com/<organization>/SciOS
```

---

# Software Citation

Software citations should include:

- Author(s)
- Project Name
- Version
- Release Date
- Repository
- DOI (if available)

---

# Research Papers

When citing a SciOS publication, reference the official published
version whenever possible.

If unavailable, cite:

- arXiv
- preprint
- technical report

in that order of preference.

---

# Artifact Citation

SciOS treats research artifacts as first-class research objects.

Artifacts include:

- Figures
- Tables
- Equations
- Datasets
- Models
- Benchmarks
- Workflows

Each artifact should include metadata identifying:

- Artifact ID
- Version
- Author
- Date
- License
- Related Publication

Example:

```
Figure F-0001

SciOS Kernel Architecture

Version 1.0
```

---

# Dataset Citation

Datasets should include:

- Dataset Name
- Authors
- Version
- Publication Year
- DOI (if available)
- Repository

Whenever possible, use persistent identifiers such as DOI.

---

# Model Citation

Machine learning models should include:

- Model Name
- Version
- Authors
- Training Dataset
- Source Repository
- License

---

# External Resources

External software, datasets, and models should always be cited
according to their original citation recommendations.

Never remove or replace original attribution.

---

# Citation Formats

SciOS supports common academic formats, including:

- BibTeX
- APA
- IEEE
- ACM
- Vancouver
- Chicago

BibTeX entries should be maintained in:

```
references.bib
```

for each research paper.

---

# Citation Files

Citation-related files include:

```
CITATION.cff
references.bib
doi.txt
publisher_link.md
arxiv.md
```

---

# Persistent Identifiers

Where available, include persistent identifiers such as:

- DOI
- ORCID
- arXiv ID
- Zenodo DOI

These identifiers improve discoverability and reproducibility.

---

# Authorship

Authorship should follow accepted academic standards.

Authors should have made substantial intellectual contributions to:

- Research
- Software
- Documentation
- Experimental Design
- Data Analysis

Contributors who do not meet authorship criteria should be acknowledged.

---

# Acknowledgements

Researchers are encouraged to acknowledge:

- Funding agencies
- Institutions
- Collaborators
- Open-source communities
- Infrastructure providers

where appropriate.

---

# Reproducibility

Citations should enable readers to reproduce published results.

Whenever possible, provide references to:

- Source Code
- Datasets
- Models
- Workflows
- Notebooks
- Supplementary Materials

---

# Versioning

Always cite the exact software version used during research.

Do not cite development versions unless explicitly required.
